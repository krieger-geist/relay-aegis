Evidence-driven self-healing for software you operate

When an app goes down, most tools page a human. RELAY finds out why, fixes what is safe to fix, and marks nothing as fixed until fresh health checks pass.

How it works

RELAY checks each app every 60 seconds. When one fails, every step leaves a record.

1

Detect

Opens an incident on crashes, failing health checks, bad deploys and SLO burn, and collects evidence from the container and its logs.

2

Diagnose

Deterministic rules match the failure to its cause, so the same evidence always gives the same answer.

3

Act safely

Every recovery passes a policy, an attempt limit and a circuit breaker, and lands in an audit trail.

4

Verify

An incident closes only after fresh health checks pass. An action that ran is not proof that it worked.

What else it does

  • Rolls back bad deploys and warns early on SLO burn
  • Writes a post-incident report for every incident, from stored records only
  • Reliability scorecard: MTTR counts only verified recoveries
  • PagerDuty alerts, role-based access and audit export
  • Checks dependencies against the OSV vulnerability database

Safe to share in public

  • Only the admin can change healing policies on the live demo
  • Each visitor gets a fair hourly limit
  • The demo watches one safe demo app, so nobody can point it at someone else's system

Run it on your own machine

You need Docker Desktop and Git. Then add your own apps the same way as the demo app.

git clone https://github.com/krieger-geist/relay-aegis.git
cd relay-aegis
cp .env.example .env        # Windows: copy .env.example .env
docker compose up -d --build
# open http://localhost:5173 and sign up
